# NexSale-B2B
 
**English** · [Español](README.es.md)
 
> 🚧 **Work in progress.** Users, products and orders have full CRUD and the security features are in place; a few items are still pending (see [Roadmap](#roadmap)).
 
Transactional backend for managing B2B orders and sales. A REST API built with **FastAPI** that handles users with different roles, a product catalogue with stock control, customer orders with a status workflow and invoice generation, all deployed with **Docker Compose** behind an **Apache** reverse proxy.
 
Developed for the *Advanced Programming Techniques* course at the Zagreb University of Applied Sciences (TVZ).
 
## Features
 
- **JWT authentication** (OAuth2 password flow) with 8-hour sessions.
- **Role-based access control** with three roles:
  | Role | Permissions |
  |---|---|
  | `admin` | Everything, including users, settings and deleting orders |
  | `commercial` | Browse the catalogue, create orders and manage **their own** orders |
  | `warehouse` | Manage products, stock and product images |
- **User management** (admin): create, edit, delete and **deactivate** users. Deactivated users cannot log in and their open sessions stop working immediately. Admins cannot delete, deactivate or change the role of their own account.
- **Product catalogue**: full CRUD, sorting, filtering by category, a computed stock status and product images stored as a BLOB (`MEDIUMBLOB`, up to 16 MB).
- **Orders**:
  - Several line items per order, with stock checks and stock reduction inside a single transaction.
  - Status workflow `pending → shipped → completed`, or `cancelled`. Completed and cancelled orders are final.
  - Cancelling or deleting an open order returns its stock.
  - Sorting and filtering by customer name.
  - Customer tax ID validation (Croatian OIB).
- **Invoices**: any order can be downloaded as a **PDF** or **RTF** invoice (order header + line items). Every invoice is **digitally signed** (RSA-PSS + SHA-256); the signature is sent in the `X-Signature` response header and can be checked with `/security/verify`. Concurrent report generation is limited with a semaphore, and a mutex protects the shared counter of active reports.
- **Concurrency safety**: stock rows are locked with `SELECT … FOR UPDATE` in a fixed order to avoid overselling and deadlocks.
- **Supplier directory (JSON file)** and **carrier list (XML file)**: data that does not live in MySQL. Each file supports adding, reading, editing and deleting records, protected by a lock to avoid lost updates. Suppliers can be filtered by category.
- **Application settings in an INI file** (`config/settings.ini`): company name and currency for invoices and the low-stock threshold. The admin can read and change them at runtime.
- **Security**:
  - Passwords hashed with SHA-256, a **variable salt derived from a rule** (from the immutable user ID, never stored) and a **random pepper** from a 52-value range that is never stored either: at login, every possible pepper is tried, always the full range so the login time is constant.
  - The customer tax ID is **encrypted at rest with AES-256-GCM**, transparently, through a custom SQLAlchemy column type.
  - **RSA-2048 (OAEP) secure inbox**: the API publishes its public key so clients can send encrypted data that only the server can read.
  - **Digital signatures** (RSA-PSS): invoices are signed with the server private key, and anyone with a session can verify their authorship and integrity.
- **Web portal**: a lightweight HTML frontend served by Apache.
- **Interactive API docs** generated by FastAPI at `/docs` and `/redoc`.
## Tech stack
 
| Layer | Technology |
|---|---|
| API | Python 3.11, FastAPI, Pydantic, Uvicorn |
| Persistence | SQLAlchemy 2, MySQL 8 (PyMySQL) |
| Security | PyJWT, `hashlib` (SHA-256 + rule-based salt + pepper), `cryptography` (AES-256-GCM, RSA-OAEP, RSA-PSS) |
| Reports | fpdf2 (PDF), RTF |
| Configuration and files | python-dotenv (`.env`), `configparser` (INI), `json`, `xml.etree.ElementTree` |
| Infrastructure | Docker, Docker Compose, Apache httpd 2.4 (reverse proxy) |
 
## Architecture
 
```text
            ┌────────────────────────────── nexsale_net ──────────────────────────────┐
 Browser ──►│  Apache :80  ──(/auth, /products, /orders, /users,  ──►  FastAPI :8000  │
            │     │            /settings, /security, /docs)                │          │
            │     └── serves frontend/index.html                           ▼          │
            │                                                         MySQL :3306     │
            └─────────────────────────────────────────────────────────────────────────┘
```
 
The code is organised in layers (router → service → model):
 
```text
server/
├── main.py          Entry point and router registration
├── routers/         HTTP endpoints (auth, users, products, orders, suppliers, carriers, settings, security)
├── services/        Business logic (orders, stock, users, reports, JSON/XML files, settings, security)
├── schemas/         Pydantic validation and response models
├── models.py        SQLAlchemy ORM models (+ encrypted column type)
├── constants.py     User roles and order statuses
├── api/deps.py      Dependencies: current user, RoleChecker
└── core/            Configuration and security
    ├── config.py        Environment variables and key validation
    ├── security.py      Password hashing and JWT
    ├── crypto.py        AES-256-GCM encryption
    ├── rsa_crypto.py    RSA keys, OAEP encryption and PSS signatures
    └── app_settings.py  INI settings
frontend/            Static web portal
apache/              Reverse proxy image and virtual host
scripts/             Database seeding, RSA key generation and demo client
config/              Runtime settings file (generated, not versioned)
data/                suppliers.json and carriers.xml (generated, not versioned)
keys/                RSA key pair (generated, never versioned)
```
 
## Getting started
 
**Requirements:** Docker and Docker Compose.
 
1. Clone the repository:
```bash
git clone https://github.com/enekorodriguezg/NexSale-B2B.git
cd NexSale-B2B
```
 
2. Create the environment file and fill in every value:
```bash
cp .env.example .env
```
 
   | Variable | Description |
   |---|---|
   | `MYSQL_ROOT_PASSWORD`, `MYSQL_DATABASE`, `MYSQL_USER`, `MYSQL_PASSWORD` | MySQL credentials |
   | `MYSQL_PORT` | MySQL port (keep `3306`: the API also uses it to reach the database) |
   | `SECRET_KEY` | Key used to sign JWTs (at least 32 characters) |
   | `AES_KEY` | 32-byte AES key in Base64. **The API will not start without it.** |
   | `RSA_KEYS_DIR`, `SETTINGS_FILE_PATH`, `DATA_DIR` | Optional: custom locations for the RSA keys, the INI file and the JSON/XML data files |
 
   The comments in `.env.example` show how to generate each key, for example:
 
```bash
python -c "import os, base64; print(base64.b64encode(os.urandom(32)).decode())"
```
 
3. Build and start the services:
```bash
docker compose up --build
```
 
4. Generate the RSA key pair (only once):
```bash
docker compose exec nexsale_api python scripts/generate_rsa_keys.py
```
 
   The keys are written to `keys/` through a Docker volume, so they survive rebuilds. The script refuses to overwrite existing keys.
 
5. Open:
   - Web portal: <http://localhost>
   - API docs: <http://localhost/docs>
On startup the API creates the tables, creates `config/settings.ini` with default values if it does not exist, and seeds three demo users (`admin`, `user_com`, `user_ware`) defined in `scripts/seed_users.py`. **They are for local development only**: change their credentials before deploying anywhere else.
 
> **Schema changes:** tables are created with `create_all`, which does not alter existing tables. After a model change, recreate the database with `docker compose down -v` (this deletes all data).
 
### RSA secure inbox demo
 
`scripts/send_secure_message.py` is an independent client: it downloads the public key, encrypts a message locally and sends it to the API, which decrypts it with its private key.
 
```bash
docker compose exec -e NEXSALE_URL=http://apache nexsale_api python scripts/send_secure_message.py "HR1210010051863000160"
```
 
## API overview
 
| Method | Endpoint | Roles |
|---|---|---|
| `POST` | `/auth/login` | public |
| `GET` | `/auth/me` | any authenticated user |
| `GET` / `POST` | `/users` | admin |
| `PUT` / `DELETE` | `/users/{id}` | admin |
| `GET` | `/products?order_by=&sort_order=&category=` | all |
| `POST` | `/products` | admin, warehouse |
| `PUT` / `DELETE` | `/products/{id}` | admin, warehouse |
| `PUT` / `GET` | `/products/{id}/image` | admin, warehouse / all |
| `GET` | `/orders?order_by=&sort_order=&customer=` | all (commercials only see their own) |
| `POST` | `/orders` | admin, commercial |
| `PUT` | `/orders/{id}` | admin, commercial (own orders) |
| `DELETE` | `/orders/{id}` | admin |
| `GET` | `/orders/{id}/report?format=pdf\|rtf` | public (see [Roadmap](#roadmap)) |
| `GET` / `POST` | `/suppliers?category=` | admin, warehouse |
| `PUT` / `DELETE` | `/suppliers/{code}` | admin, warehouse |
| `GET` | `/carriers` | all |
| `POST` | `/carriers` | admin, warehouse |
| `PUT` / `DELETE` | `/carriers/{code}` | admin, warehouse |
| `GET` / `PUT` | `/settings` | admin |
| `GET` | `/security/public-key` | public |
| `POST` | `/security/decrypt` | admin |
| `POST` | `/security/verify` (multipart: `file`, `signature`) | any authenticated user |
| `GET` | `/health` | public |
